  <action>
    1. Update the RedrawRequested handler in `crates/ora/src/platform/event_loop.rs`:
       - On RedrawRequested:
         a. Call `ora_window.render(&mut view_context)` to get `Option<AnyElement>` tree from root view
         b. If element tree exists, drive it through the three phases:
            - Create LayoutContext, call `element.request_layout(&mut layout_cx)`
            - Create PrepaintContext, call `element.prepaint(&mut prepaint_cx)`
            - Create PaintContext (wrapping GpuState access), call `element.paint(&mut paint_cx)`
         c. Call `gpu_state.present()` to submit GPU commands and present frame
         d. Request next redraw for continuous rendering
       - This is the core render loop. Every frame: render view -> build element tree -> lifecycle phases -> GPU present.

    2. Flesh out PaintContext in `crates/ora/src/element/trait_def.rs`:
       - PaintContext needs to collect rendering commands from elements during paint phase
       - Add a `paint_commands: Vec<PaintCommand>` field to PaintContext
       - Define `pub enum PaintCommand`:
         - `Rect { x: f32, y: f32, width: f32, height: f32, color: [f32; 4] }` -- colored rectangle
       - PaintContext methods:
         - `pub fn paint_rect(&mut self, x: f32, y: f32, width: f32, height: f32, color: [f32; 4])` -- adds a Rect command
         - `pub fn window_size(&self) -> (u32, u32)` -- returns current window dimensions
       - Also flesh out LayoutContext:
         - `pub fn request_layout(&mut self) -> LayoutId` -- returns next sequential LayoutId (stub layout: no actual constraint solving in Phase 1; real layout comes in Phase 2)
       - Also flesh out PrepaintContext:
         - Minimal for Phase 1; just holds window size. Hitbox registration comes in Phase 4.

    3. Update `crates/ora/src/platform/gpu.rs`:
       - Add `pub fn render_commands(&mut self, commands: &[PaintCommand]) -> Result<(), wgpu::SurfaceError>`:
         - Gets current texture and creates render pass with dark clear color
         - For Phase 1 stub rendering, the paint commands are collected but the actual colored rectangles are rendered via the clear color only. To produce visible proof-of-concept:
           - Option A (simpler): If any Rect commands exist, use the first rect's color as the clear color for the entire frame. This proves the pipeline works without needing a vertex buffer.
           - Option B (better): Create a minimal wgpu render pipeline with a hardcoded vertex/fragment shader that draws colored quads from the PaintCommand list. This is closer to the real Phase 2 pipeline.
         - Claude should use their judgment: Option A is sufficient for Phase 1's goal of proving the lifecycle works. Option B is better if it doesn't add too much complexity. Either approach is acceptable.
       - The existing `render()` method from Plan 01 can be replaced by `render_commands()`.

    4. Ensure the lifecycle ordering is correct in the render loop:
       - View::render() produces AnyElement tree (called once per frame when view needs redraw)
       - request_layout traverses tree top-down, each element returns LayoutId
       - prepaint traverses tree (hitbox registration -- stub in Phase 1)
       - paint traverses tree, each element adds PaintCommands to PaintContext
       - GpuState::render_commands() executes collected commands

       ```rust
       struct ColorRect {
           color: [f32; 4],
           x: f32, y: f32,
           width: f32, height: f32,
       }

       impl Element for ColorRect {
           type RequestLayoutState = ();

           fn request_layout(&mut self, cx: &mut LayoutContext) -> (LayoutId, ()) {
               (cx.request_layout(), ())
           }

           fn prepaint(&mut self, _state: &mut (), _cx: &mut PrepaintContext) {
               // No hitboxes in Phase 1
           }

           fn paint(&mut self, _state: &mut (), cx: &mut PaintContext) {
               cx.paint_rect(self.x, self.y, self.width, self.height, self.color);
           }
       }
       ```

    2. Define a `HelloView` that implements View:
       ```rust
       struct HelloView {
           frame_count: u64,
       }

       impl HelloView {
           fn new() -> Self {
               Self { frame_count: 0 }
           }
       }

       impl View for HelloView {
           fn render(&self, _cx: &mut ViewContext) -> AnyElement {
               // Create a root element with colored children
               let root = ColorRect {
                   color: [0.2, 0.3, 0.8, 1.0], // Blue background
                   x: 50.0, y: 50.0,
                   width: 300.0, height: 200.0,
               };

               let child = ColorRect {
                   color: [0.9, 0.2, 0.3, 1.0], // Red foreground
                   x: 100.0, y: 100.0,
                   width: 100.0, height: 80.0,
               };

               AnyElement::new(root)
                   .with_children(vec![AnyElement::new(child)])
           }
       }
       ```

    3. Main function:
       ```rust
       fn main() {
           ora::App::new()
               .title("ora - hello world")
               .size(800, 600)
               .on_open(|cx| {
                   cx.set_root_view(HelloView::new());
               })
               .run();
       }
       ```

       - Display colored rectangles from the View's element tree
       - Handle resize without crashing
