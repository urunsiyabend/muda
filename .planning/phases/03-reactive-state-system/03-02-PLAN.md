Create `ora/src/subscription.rs` with:

1. `SubscriptionId` -- a simple `usize` newtype or alias for identifying subscriptions.

2. `Subscription` struct:
   - `id: SubscriptionId`
   - `cleanup: Option<Box<dyn FnOnce()>>` -- called on Drop to remove from registry
   - `pub fn detach(mut self)` -- takes cleanup (sets to None), preventing Drop cleanup. The subscription stays alive forever (useful for view-lifetime subscriptions set up in init).

3. `impl Drop for Subscription`:
   - If cleanup is Some, call the cleanup function to unregister from the registry.

4. `ObserverCallback` type alias: `Box<dyn FnMut()>` -- observer callbacks are simple "re-render signal" closures that don't receive event data (per CONTEXT.md: "Observe callback receives notification only (view, cx) -- just a signal to re-render").

   In practice, since we can't pass `&mut V` and `&mut ViewContext<V>` through a type-erased Box, the callback will be a closure that captures what it needs. The simplest approach: the callback captures the observer's EntityId and calls a "mark dirty" function. This avoids generic lifetime issues.

   So the real callback type: `Box<dyn FnMut(&mut AppContext)>` -- receives mutable AppContext so it can mark entities dirty, request redraws, etc.

5. `ObserverSet` struct:
   - `observers: HashMap<EntityId, Vec<(SubscriptionId, Box<dyn FnMut(&mut AppContext)>)>>` -- map from observed entity to list of observer callbacks
   - `next_id: SubscriptionId`

6. `ObserverSet` methods:
   - `pub fn new() -> Self`
   - `pub fn add_observer(&mut self, observed: EntityId, callback: Box<dyn FnMut(&mut AppContext)>) -> SubscriptionId` -- inserts callback, returns sub ID
   - `pub fn remove_observer(&mut self, observed: EntityId, id: SubscriptionId)` -- removes specific callback
   - `pub fn take_observers_for(&mut self, entity_id: EntityId) -> Vec<Box<dyn FnMut(&mut AppContext)>>` -- temporarily takes all callbacks for an entity (for safe invocation without borrowing ObserverSet). After invocation, they must be put back via `restore_observers`.
   - `pub fn restore_observers(&mut self, entity_id: EntityId, callbacks: Vec<(SubscriptionId, Box<dyn FnMut(&mut AppContext)>)>)` -- puts callbacks back after invocation

   Alternative simpler approach: instead of take/restore, use indices. But take/restore is cleaner for borrow checker since we need `&mut AppContext` in callbacks while ObserverSet is part of AppContext.

   IMPORTANT BORROW PATTERN: Since ObserverSet is a field of AppContext, and callbacks need `&mut AppContext`, we must temporarily move observers out of AppContext before invoking them. Pattern:
   ```rust
   let observers = std::mem::take(&mut self.observer_set.observers);
   for (entity_id, callbacks) in &mut observers {
       for (_id, callback) in callbacks {
           callback(self);
       }
   }
   self.observer_set.observers = observers;
   ```
   This is the standard GPUI pattern for avoiding self-referential borrows.

REFACTOR: Change OraApp to own AppContext directly instead of swapping EntityStorage in and out. AppContext should persist across frames. This is the Phase 3 architectural upgrade.

   Specifically in `event_loop.rs`, OraApp should store `app_context: AppContext` instead of `entity_storage: EntityStorage`. The `resumed()` and `window_event()` methods use `&mut self.app_context` directly instead of swapping storage.

5. Replace the stub `flush_effects()` with real implementation:
   ```
   const DEPTH_LIMIT: usize = 10;

   fn flush_effects(&mut self) {
       let mut depth = 0;
       loop {
           depth += 1;
           if depth > DEPTH_LIMIT {
               panic!("Effect cascade depth limit exceeded ({}). Possible infinite loop in observers.", DEPTH_LIMIT);
           }
           if depth > 5 {
               log::warn!("Effect cascade depth {} (limit: {})", depth, DEPTH_LIMIT);
           }

           // Priority 1: Process all notify effects
           let notified = self.effect_queue.drain_notify();
           if notified.is_empty() && self.effect_queue.is_empty() {
               break; // All queues empty
           }

           for entity_id in notified {
               self.dirty_entities.insert(entity_id);
               // Invoke observers -- take observers out, invoke, put back
               // (see borrow pattern from Task 1)
               // Each observer callback may queue more effects
           }

           // Priority 2: Process all emit effects (Plan 03 will implement)
           let _emitted = self.effect_queue.drain_emit();
           // TODO(Plan 03): dispatch to subscribers

           // If new effects were queued during processing, loop again
           if self.effect_queue.is_empty() {
               break;
           }
       }
   }
   ```

   - Returns Subscription with cleanup closure that removes from observer_set
   - For the cleanup closure, use a shared reference to the observer_set. Since ObserverSet is inside AppContext and Subscription's Drop can't access AppContext, use a different approach: store cleanup info (observed EntityId + SubscriptionId) and use a global or thread-local cleanup queue that AppContext drains periodically. OR simpler: make Subscription's cleanup a no-op for now and rely on entity removal to clean up. OR: use Rc<RefCell<ObserverSet>> pattern.

   SIMPLEST SAFE APPROACH: Subscription stores (observed_entity_id, subscription_id). Drop pushes to a thread-local "pending cleanups" Vec. AppContext::flush_effects() drains pending cleanups first. This avoids Rc<RefCell> and is safe.

   Actually even simpler for v1: `Subscription::detach()` is the primary API (GPUI pattern). Subscriptions set up at view init call `.detach()` so they live as long as the view. When the view entity is dropped, the view's data (which includes any state referencing the subscription) is dropped. For entities that are removed, AppContext::remove should also clean up any observers registered for that entity. Add `pub fn remove_model<T: 'static>(&mut self, model: &Model<T>) -> Option<T>` that also cleans up observer_set entries for that entity.
