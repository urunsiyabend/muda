**In core_editor/src/app.rs — get_open_views_info():**

Currently iterates `self.workspace.views()` which is HashMap iteration (random order). Change to iterate `self.workspace.tab_order()`:

```rust
fn get_open_views_info(&self) -> Vec<(u64, String, bool, bool)> {
    let active_view_id = self.workspace.active_view_id();

    self.workspace.tab_order()
        .iter()
        .filter_map(|view_id| {
            let view = self.workspace.view(*view_id)?;
            let doc = self.workspace.document(view.document_id())?;
            let title = doc.title();
            let is_active = Some(*view_id) == active_view_id;
            let is_dirty = doc.is_dirty();
            Some((view_id.as_u64(), title, is_active, is_dirty))
        })
        .collect()
}
```

**Approach:** Use the existing `Tab` element (`ora/src/elements/tab.rs`) which already has `on_click` and `on_close` callback fields, hitbox registration for both the tab body and close button, and all the visual styling (active accent border, dirty dot indicator, hover states). The TabBarView currently renders raw Divs — refactor it to use the `Tab` element instead.

**Key discovery:** The Tab element defines `on_click`/`on_close` callbacks and registers hitboxes during prepaint, BUT the callbacks are never wired to the framework's `register_mouse_down` event dispatch system. The framework has `cx.on_mouse_down(hitbox_id, handler)` in `PrepaintContext` (see `ora/src/element/trait_def.rs:265`). The Button, Tab, and other elements define callbacks but don't call `register_mouse_down`. This is the missing link.

**Step 1: Wire Tab element callbacks to event dispatch**

In `ora/src/elements/tab.rs`, in the `prepaint` method, after registering the hitbox:

```rust
fn prepaint(&mut self, state: &mut Self::RequestLayoutState, cx: &mut PrepaintContext) {
    let bounds = cx.bounds(state.layout_id);
    let hitbox_id = cx.register_hitbox(bounds, true);
    state.hitbox_id = Some(hitbox_id);

    // Wire on_click callback to mouse event dispatch
    if let Some(on_click) = self.on_click.take() {
        cx.on_mouse_down(hitbox_id, move |_event, _ctx| {
            on_click();
        });
    }

    // Wire on_close callback to close button hitbox
    if self.show_close {
        // ... existing close_bounds calculation ...
        let close_hitbox_id = cx.register_hitbox(close_bounds, false);
        state.close_hitbox_id = Some(close_hitbox_id);

        if let Some(on_close) = self.on_close.take() {
            cx.on_mouse_down(close_hitbox_id, move |_event, _ctx| {
                on_close();
            });
        }
    }
    // ... rest of prepaint ...
}
```

Note: Use `.take()` to move the callback out of self (it's `Option<Box<dyn Fn()>>`). The callback is consumed each frame but TabBarView rebuilds Tab elements every render cycle so this is fine.

Also add middle-click handling: Check `MouseDownEvent` for button field. If the event carries `MouseButton::Middle`, dispatch close. In the main tab hitbox handler:

```rust
if let Some(on_close_for_middle) = self.on_close.as_ref().map(|_| { /* clone issue */ }) {
    // Alternative: register a separate handler that checks button
}
```

For middle-click, the simplest approach: in the tab body `on_mouse_down` handler, check the event button. If middle (button == 1 in many frameworks, or MouseButton::Middle), call on_close instead of on_click.
