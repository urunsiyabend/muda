# Phase 14.1 Plan 01: Paint-Phase Scroll Offset Summary

**PaintOffsetElement introduced and wired into TextAreaView (4 sites) and GutterView (1 site), eliminating all mt()-based fractional scroll offsets and making the element tree layout-stable across scroll frames.**

## Performance

- **Duration:** 6 min
- **Started:** 2026-03-28T08:16:55Z
- **Completed:** 2026-03-28T08:22:48Z
- **Tasks:** 2
- **Files modified:** 4 (+ 1 created)

## Accomplishments

- Created `PaintOffsetElement` in `ora/src/elements/paint_offset.rs`: a zero-layout-cost wrapper that applies `push_offset`/`pop_offset` in paint phase only; exported as `paint_offset(dy, child)` constructor
- Removed all 4 `mt(-self.scroll_y_offset_px)` / `mt(scroll_shift)` calls from TextAreaView — replaced with `paint_offset` in `render_current_line_bg_layer`, `render_selection_bg_layer`, Layer 4 (text), and Layer 5 (caret)
- Removed the single `mt(shift)` call from GutterView — replaced with `paint_offset`
- Element tree structure is now layout-stable across scroll frames: flexbox computation sees no margin changes between frames

## Task Commits

Each task was committed atomically:

1. **Task 1: Replace mt(scroll_shift) with push_offset in TextAreaView** - `c71b3e9` (feat)
2. **Task 2: Replace mt(shift) with push_offset in GutterView** - `1d65179` (feat)

## Files Created/Modified

- `ora/src/elements/paint_offset.rs` — New `PaintOffsetElement` struct implementing `Element`; `paint_offset(dy, child)` constructor; delegates `request_layout`/`prepaint` to child, wraps `paint` with `push_offset`/`pop_offset`
- `ora/src/elements/mod.rs` — Added `pub mod paint_offset` and `pub use paint_offset::{paint_offset, PaintOffsetElement}`
- `ora/src/views/text_area.rs` — Replaced 4 `mt()` scroll offset calls with `paint_offset()`; imported `paint_offset` from elements
- `ora/src/views/gutter.rs` — Replaced 1 `mt()` scroll offset call with `paint_offset()`; imported `paint_offset` from elements

## Decisions Made

- `PaintOffsetElement::request_layout` returns the child's `LayoutId` directly — the wrapper element has no layout node of its own, so the child participates in flexbox exactly as before
- `paint_offset` wraps the inner content `Div` (the one holding rows), not the `overflow_hidden` container — clipping via scissor rect still works correctly because `push_clip` is applied by the outer container before `paint_offset` shifts the content
- Single shared `PaintOffsetElement` definition reused by both TextAreaView and GutterView (no duplication)
- Explicit `: AnyElement` type annotation needed on inner divs passed to `paint_offset` to resolve ambiguous `Into<_>` inference

## Deviations from Plan

None — plan executed exactly as written.

## Issues Encountered

- Rust type inference error: `let inner = Div::new()...into()` was ambiguous without explicit `: AnyElement` annotation because `Div` implements `Into<AnyElement>` but the inference target was unclear. Fixed with `let inner: AnyElement = ...`
- Pre-existing test failures in `core_editor` (`test_paste_line_copy_inserts_above_current_line`, `test_paste_with_selection_replaces_selection`) confirmed pre-existing by stash check — unrelated to this plan
