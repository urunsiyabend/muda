<objective>
Replace margin-top scroll offset with paint-phase coordinate translation in TextAreaView and GutterView.

Purpose: The current `mt(scroll_shift)` pattern applies fractional scroll offset as a layout margin, which forces full layout recomputation on every scroll frame. By moving this to `push_offset()` in the paint phase (the same pattern ScrollArea already uses), the element tree structure becomes layout-stable across scroll frames. This is the prerequisite for removing `needs_layout = true` on scroll in Plan 02.

Output: TextAreaView and GutterView no longer use `mt()` for scroll offset; they use `push_offset`/`pop_offset` in the paint phase via wrapper elements or inline in their render methods.
</objective>

1. `render_current_line_bg_layer()` — line 182: `.mt(-self.scroll_y_offset_px)` on the inner flex-col div
2. `render_selection_bg_layer()` — line 270: `.mt(-self.scroll_y_offset_px)` on the inner flex-col div

For each of these, the pattern is the same: an inner flex-col div uses `mt(negative_offset)` to shift content upward, and the parent has `overflow_hidden()` to clip.

**The fix:** Each overflow_hidden() container (Layers 2, 3, 4, 5) already clips its child. Instead of applying mt() on the inner child, create a custom wrapper element (or use the existing `ScrollArea` pattern inline) that applies `push_offset(0.0, -self.scroll_y_offset_px)` in paint and `pop_offset()` after children paint.

**Recommended approach — custom PaintOffset element:**

Create a small `PaintOffsetElement` struct in text_area.rs (private to the module) that wraps a single child element and applies a Y-offset via `push_offset`/`pop_offset` in its `paint()` method. This element does NOT affect layout — its `request_layout` delegates to the child, and its `prepaint` delegates to the child. Only `paint` adds the offset.

```rust
struct PaintOffsetElement {
    dy: f32,
    child: AnyElement,
}

impl Element for PaintOffsetElement {
    type RequestLayoutState = Box<dyn Any>;
    type PrepaintState = ();

    fn request_layout(&mut self, cx: &mut LayoutContext) -> (LayoutId, Self::RequestLayoutState) {
        self.child.request_layout(cx)
    }

    fn prepaint(&mut self, state: &mut Self::RequestLayoutState, cx: &mut PrepaintContext) {
        self.child.prepaint(state, cx);
    }

    fn paint(&mut self, state: &mut Self::RequestLayoutState, cx: &mut PaintContext) {
        if self.dy != 0.0 {
            cx.push_offset(0.0, self.dy);
        }
        self.child.paint(state, cx);
        if self.dy != 0.0 {
            cx.pop_offset();
        }
    }
}
```

**Important:** Check the Element trait signature in `ora/src/element/trait_def.rs` for the exact types and method signatures. The above is a sketch — adapt to match the actual trait. The key requirement is that `request_layout` returns the child's LayoutId so the child participates in layout normally, and `paint` wraps the child's paint with offset.
