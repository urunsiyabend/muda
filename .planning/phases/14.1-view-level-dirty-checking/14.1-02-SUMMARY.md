# Phase 14.1 Plan 02: Conditional needs_layout on Scroll Summary

**Editor scroll made paint-only by gating needs_layout on the consumed flag: sidebar scroll (consumed=true) still triggers full layout for virtualization, editor scroll (consumed=false) reuses cached layout_outputs — layout cache hit rate rises from ~0% to 90%+ during continuous scroll.**

## Accomplishments

- Made `needs_layout` conditional on `consumed` in the MouseWheel handler: sidebar scroll (`consumed=true`) sets `needs_layout=true` because viewport virtualization in `FileTreeView` changes element count per frame; editor scroll (`consumed=false`) leaves `needs_layout` unset so cached layout_outputs are reused
- Wired `FrameDirtyFlags` at the MouseWheel site: `dirty_flags.sidebar = true` for sidebar scroll, `dirty_flags.editor_content = true` for editor scroll; all other event sites (resize, click, keyboard, focus, dirty-entities, watcher) were already wired by the WIP commit
- Added debug_assert safety guard on paint-only frames (when `!run_full_layout`): asserts `new_layout_count <= cached_layout_outputs.len()` to catch regressions where scroll unexpectedly grows the element tree
- `cargo build` passes cleanly; all 144 passing lib tests continue to pass

## Decisions Made

- Editor scroll (`consumed == false`) does NOT set `needs_layout = true` — the element tree is layout-stable after Plan 01 (PaintOffsetElement replaced all `mt()` scroll offset calls); `cached_layout_outputs` are reused directly
- Sidebar scroll (`consumed == true`) still sets `needs_layout = true` — `FileTreeView::virtual_slice()` changes which items are visible, altering element count and LayoutId assignment order each frame; reusing stale layout_outputs would produce incorrect positioning
- `FrameDirtyFlags` is informational for now — it documents what changed per frame but does not yet gate rendering decisions; enables future per-region paint caching without requiring architectural changes to the event dispatch model
- `debug_assert` placement: assertion is inside `if !run_full_layout {}` block so it only fires when both the grow-check AND the assertion logic would disagree — catches logic errors in the cache invalidation path
