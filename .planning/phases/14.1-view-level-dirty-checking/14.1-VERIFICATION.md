## SC2 Precision Note

The SUMMARY claims non-scrolling views have zero layout or render cost during editor scroll. The actual implementation is more precise: prepaint and paint still traverse the full element tree on every frame - only compute_flexbox (the expensive layout phase) is skipped and cached flexbox bounds are reused. The measured 0.75ms paint-only CPU cost confirms this is architecturally sound. The goal criterion is met: zero layout computation cost for unchanged regions. Future work (true per-region paint command caching using FrameDirtyFlags) could eliminate the prepaint/paint traversal cost for static views.

## Significant Off-Plan Work

The following work was completed during Phase 14.1 outside plan scope. None creates gaps against Phase 14.1 success criteria.

1. **Text-area scroll flicker fix (commit ce5a2ac):** TextElement defaulted to Length::Auto width causing w=0 glyphon clip on empty lines, which clipped newly-populated line slots on paint-only scroll frames. Fixed by wrapping each line row in a flex_row Div and giving TextElement grow(1.0). Confirmed in code: render_line() uses .flex_row() + TextElement::rich(...).grow(1.0). Directly enables SC3.

2. **glyphon 0.7 to 0.10 + wgpu 23 to 28 upgrade:** Rust toolchain pinned to 1.92.0; cosmic-text 0.15 API migrated; wgpu 28 API migrated. No gaps introduced.

3. **Rich-text infrastructure:** TextRun, measure_rich_text_cached, paint_rich_text_cached, TextElement::rich(Vec<TextRun>) added. Powers per-span syntax highlighting. No gaps.

4. **Shrink guard in layout cache (commit 29c2499):** Forces full layout when element count changes in either direction. Confirmed at lines 1261-1262 in event_loop.rs.

5. **FileTreeView spacer stability (commit 6a00ad0):** Always-emit top/bottom spacers. Verified as part of SC4.

6. **F12 paint-command dump (commit ede4940):** One-shot diagnostic. Zero per-frame cost. Intentionally kept.
