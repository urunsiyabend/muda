3. Implement builder methods:

4. Create StackState struct:

```rust
pub struct StackState {
    layout_id: LayoutId,
    child_states: Vec<AnyElementState>,
}
```
Note: AnyElementState doesn't exist - we need a different approach. Looking at Div, children are managed internally with child.request_layout(), child.prepaint(), child.paint() calls.

Actually, match the Div pattern:
```rust
pub struct StackState {
    layout_id: LayoutId,
}
```

5. Implement Element trait:

**request_layout:**
- Call `cx.request_layout(&self.style)` to get own layout_id
- For each child, call `child.request_layout(cx)` to get child_id
- Call `cx.add_child(id, child_id)` to register parent-child relationship
- Stack layout = all children same position, size = max(children sizes) or explicit size
- Return (layout_id, StackState { layout_id })

**prepaint:**
- Get own bounds from `cx.bounds(state.layout_id)`
- For each child, call `child.prepaint(cx)`
- Children will use their own layout positions

**paint:**
- For each child in order, call `child.paint(cx)`
- First child painted first (bottom), last child painted last (top)
- This creates z-layering via paint order, no sorting needed

Key insight: Stack differs from Div only in layout semantics (children overlap vs flow). The rendering is identical - paint children in order.
