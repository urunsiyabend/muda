  <action>
  **In ora/src/editor_adapter/types.rs:**
  1. Add `pub is_deleted: bool` field to `TabPresentation`. Default to `false`. Update the `new()` constructor to accept it or add a default.

  2. Add a new `DialogPresentation` variant for external modification prompts:
     ```rust
     ExternalModificationPrompt {
         /// The file that was modified externally.
         file_name: String,
     }
     ```

  **In ora/src/editor_adapter/mod.rs:**
  3. Add method to `FileOpDataSource`:
     ```rust
     /// Check all open buffers against watcher events for file-level changes.
     /// Called after poll_watcher_events returns true.
     fn handle_external_file_changes(&mut self);
     ```

  **In wgpu_client/src/adapter.rs:**
  4. Enhance `poll_watcher_events` to not just mark tree dirty, but also collect the set of changed file paths from the debounced events. Store them in a `Vec<PathBuf>` field `pending_external_changes` on the adapter. After draining events, if the vec is non-empty, call `handle_external_file_changes()`.

  5. Implement `handle_external_file_changes`:
     - For each path in `pending_external_changes`:
       a. Check if the path corresponds to an open buffer in the workspace's buffer registry.
       b. If the file was **deleted** (path no longer exists on disk):
          - Find the buffer/document, mark it as deleted. Add a `is_deleted: bool` field to the document or buffer struct in core_editor (or track it in the adapter with a `HashSet<PathBuf>` of deleted paths).
          - The simplest approach: maintain a `deleted_paths: HashSet<PathBuf>` on `CoreEditorAdapter`. When building TabPresentation, check if the tab's path is in `deleted_paths` and set `is_deleted = true`.
       c. If the file was **modified** (path still exists):
          - Check if the buffer is dirty (has unsaved changes).
          - If NOT dirty: auto-reload. Read the file, update the buffer content. Use `std::fs::read_to_string`, validate UTF-8, strip BOM (same pattern as file loading in Phase 12). Update the document's content directly.
          - If dirty: set a pending reload prompt. Add the path to a `pending_reload_prompts: Vec<PathBuf>` on the adapter. On next render, show the `ExternalModificationPrompt` dialog for the first entry. The dialog should offer "Reload" (discard local changes, reload from disk) and "Keep" (ignore external change, keep local edits).
     - Clear `pending_external_changes` after processing.

  6. In `build_render_model` (or the tab bar presentation builder): when constructing `TabPresentation` for each tab, check if the tab's file path is in `deleted_paths`. Set `is_deleted` accordingly.

  7. Handle the dialog response for ExternalModificationPrompt — when user clicks "Reload", read file from disk and replace buffer content. When "Keep", remove from pending prompts and continue.

  8. In `handle_folder_opened`: before setting the new workspace, check for dirty buffers. If any exist, show the existing `UnsavedChangesConfirmation` dialog with action "Open Folder". If all clean (or user confirms), close all tabs via workspace, then set the new base directory. The pattern: collect dirty document titles, if non-empty show dialog, if confirmed proceed. For now, if implementing the full dialog flow is complex, a simpler approach: close all buffers, prompt only if dirty ones exist using the existing dialog infrastructure.

  **In ora/src/views/tab_bar.rs:**
  9. Render deleted indicator on tabs where `is_deleted` is true. Options:
     - Add strikethrough effect on the tab title text (use a line through the text).
     - Or change tab title color to a muted/red tone.
     - Or add a small "(deleted)" suffix.
     Choose the approach that fits the existing tab rendering pattern best. A muted color + italic styling is cleanest.
  </action>
