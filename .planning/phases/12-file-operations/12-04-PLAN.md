if let Some(adapter) = &self.editor_adapter {

    }

1. **`WindowEvent::CursorMoved`** — at the very top of the arm, before any hit testing or hover state updates.

2. **`WindowEvent::MouseInput`** — at the very top of the arm, before hit testing and mouse button dispatch.

Do NOT guard the `about_to_wait` method — the async executor must still tick to process the dialog future and receive its result.

<task type="auto">
  <name>Task 2: Make status bar messages persist for 3 seconds</name>
  <files>wgpu_client/src/adapter.rs, ora/src/platform/event_loop.rs</files>
  <action>
Change the status message mechanism from immediate `.take()` to time-based expiry:

**In `wgpu_client/src/adapter.rs`:**

1. Add `use std::time::Instant;` at the top if not already present.

2. Add a new field to `CoreEditorAdapter`:
   ```rust
   status_message_expiry: Option<Instant>,
   ```
   Initialize to `None` in all constructors (`new`, `new_with_workspace`, `new_test`).

3. Wherever `pending_status_message` is set to `Some(...)` (search for all `self.pending_status_message = Some(...)`), also set the expiry:
   ```rust
   self.status_message_expiry = Some(Instant::now() + std::time::Duration::from_secs(3));
   ```
   There are approximately 4 locations: `handle_file_error`, `handle_file_saved` (the "File saved" message), `save_active_doc` error case, and the `handle_open_result` error case. Update ALL of them.

4. In `build_render_model`, replace the `pending.take()` logic with expiry-aware logic:
   ```rust
   // Replace this:
   if let Some(msg) = pending.take() {
       render_model.status.message = Some(msg);
   }

   // With this:
   let expiry = unsafe {
       &mut (*(self as *const CoreEditorAdapter as *mut CoreEditorAdapter)).status_message_expiry
   };
   if let Some(ref msg) = *pending {
       if expiry.map_or(false, |exp| Instant::now() < exp) {
           render_model.status.message = Some(msg.clone());
       } else {
           // Expired — clear both
           *pending = None;
           *expiry = None;
       }
   }
   ```

**In `ora/src/platform/event_loop.rs`:**

5. In `about_to_wait`, schedule a redraw at the message expiry time so the message clears itself. After the existing caret blink logic, add: if the adapter has a non-None `status_message_expiry`, use `WaitUntil` with the minimum of the blink instant and the expiry instant. This requires exposing `status_message_expiry()` on the adapter.

   Simpler alternative (PREFERRED): In `build_render_model`, when the message is still active (not expired), request a redraw by calling `self.app.needs_render = true` so the next frame checks again. The event loop already redraws when `has_dirty_entities()` is true. The message will disappear on the first frame after expiry. This avoids adding a new trait method. Actually, since `build_render_model` is called every frame during redraw, the message will naturally persist across redraws. The only issue is triggering a redraw AFTER the 3-second expiry to clear it.

   Best approach: Add a `status_message_expiry` getter to the `FileOpDataSource` trait in `ora/src/editor_adapter/mod.rs`:
   ```rust
   fn status_message_expiry(&self) -> Option<std::time::Instant>;
   ```
   Implement it on `CoreEditorAdapter` to return `self.status_message_expiry`.

   In `about_to_wait` in event_loop.rs, after the blink logic, check:
   ```rust
   if let Some(adapter) = &self.editor_adapter {
       if let Some(expiry) = adapter.borrow().status_message_expiry() {
           if expiry > Instant::now() {
               // Ensure we wake up to clear the message
               let current_cf = match event_loop.control_flow() {
                   // If already WaitUntil, pick the earlier time
                   _ => {}
               };
               // Simplest: just set WaitUntil to min of current and expiry
           }
       }
   }
   ```

   Actually, the simplest correct approach: in `about_to_wait`, collect all "wake at" instants into a single `Option<Instant>` and use the earliest. Refactor the existing blink logic to contribute to this, then add the status expiry as another contributor. The final `set_control_flow` uses the earliest instant.

   CONCRETE implementation for `about_to_wait`: After the existing `if self.app_context.has_dirty_entities() || has_active_animations` block, in the `else` branch where sleep scheduling happens, compute the earliest wake instant from both `self.next_blink_instant` and the adapter's `status_message_expiry()`. Use `Option::min()` logic:

   ```rust
   let mut earliest_wake: Option<Instant> = self.next_blink_instant;
   if let Some(adapter) = &self.editor_adapter {
       if let Some(expiry) = adapter.borrow().status_message_expiry() {
           earliest_wake = Some(match earliest_wake {
               Some(existing) => existing.min(expiry),
               None => expiry,
           });
       }
   }
   match earliest_wake {
       Some(instant) if instant > Instant::now() => {
           event_loop.set_control_flow(ControlFlow::WaitUntil(instant));
       }
       Some(_) => {
           // Past due — request redraw immediately
           if let Some(gpu_state) = &self.gpu_state {
               gpu_state.window.request_redraw();
           }
           // Re-check on next iteration
           self.next_blink_instant = self.next_blink_instant.map(|i| {
               if i <= Instant::now() { Instant::now() + BLINK_RATE } else { i }
           });
           event_loop.set_control_flow(ControlFlow::Poll);
       }
       None => {
           event_loop.set_control_flow(ControlFlow::Wait);
       }
   }
   ```

   This replaces the entire existing match on `self.next_blink_instant` with unified wake scheduling.

Also update `ora/src/editor_adapter/mod.rs` to add `status_message_expiry()` to the `FileOpDataSource` trait.
