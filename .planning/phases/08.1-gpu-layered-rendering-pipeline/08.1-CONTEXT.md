# Phase 8.1: GPU Layered Rendering Pipeline - Context

**Gathered:** 2026-03-02
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix the GPU rendering pipeline so overlay elements (command palette, dialog, toast) correctly occlude content from lower z-layers, including text rendered by glyphon. This is a rendering infrastructure fix — no new UI components or behaviors are added.

</domain>

<decisions>
## Implementation Decisions

### Rendering correctness
- Overlays must fully occlude ALL content beneath them — both rects and text
- Command palette background must completely hide editor text behind it
- Dialog backdrop + body must occlude everything from lower layers
- Toast notifications render on top of all other content without artifacts

### Performance constraint
- Single-pass rendering performance must be maintained (no excessive render pass overhead)
- Solution must not regress existing rendering of sidebar, editor, tab bar, panel, status bar

### Shadow rendering
- Shadow rendering must produce correct Gaussian falloff (strongest at box edge, fading with distance)

### Claude's Discretion
- Rendering approach (multi-pass, depth buffer, render-to-texture, or hybrid)
- glyphon TextRenderer lifecycle management (multi-prepare strategy)
- Layer boundary detection and grouping strategy
- Borrow checker workarounds for render pass interleaving
- Performance optimization within correctness constraints

</decisions>

<specifics>
## Specific Ideas

### Known constraints from prior attempts
- Current pipeline: ALL rects in one batch, then ALL text in one batch — causes text bleed-through
- Stack inserts `PaintCommand::LayerBoundary` markers between children, but renderer ignores them
- Prior multi-pass attempt (one per Stack child): caused sidebar content loss and empty command palette
- Prior two-pass attempt (base + overlays): similar rendering artifacts
- Root cause unclear: possibly bind_group invalidation, glyphon state reset, or LoadOp::Load behavior

### Research areas identified
- wgpu multi-pass rendering with `LoadOp::Load` for correct layer composition
- glyphon TextRenderer lifecycle: can prepare/render be called multiple times per frame?
- Rust borrow checker constraints: render_pass borrows prevent interleaved prepare/render
- Depth buffer approach: assign z-values to paint commands, GPU depth test handles occlusion
- Render-to-texture per layer, then composite

</specifics>
