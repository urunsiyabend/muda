# Phase 8.1 Plan 03: Layered render_frame() Integration Summary

**render_frame() rewritten with per-LayerBoundary multi-pass rendering: flat rect buffer + range slicing, all text prepares before renders, first pass Clear + subsequent passes Load — fixes overlay text bleed-through with zero overhead for the common case**

## Accomplishments

- Rewrote `render_frame()` in `ora/src/platform/gpu.rs` to implement the complete layered rendering pipeline
- Commands are grouped into per-layer `Vec` collections by splitting at `LayerBoundary` markers
- All rect instances are flattened into a single buffer with one `prepare()` call; `render_range()` slices the buffer per layer to avoid bind_group invalidation
- Text is distributed to the per-layer `TextRenderer` pool via `add_text_to_layer()`, with all `prepare_layer()` calls completing before any `render_layer()` calls to stabilize the glyphon atlas
- First render pass uses `LoadOp::Clear`, subsequent passes use `LoadOp::Load` for correct occlusion layering
- Single `queue.submit()` per frame maintains Vulkan compatibility
- All 111 existing unit tests pass with zero regressions
- Visual UAT approved by user ("LGTM"): basic layout intact, overlay occlusion correct, no console errors

## Decisions Made

- Used flat rect buffer + per-layer `Range<u32>` slicing rather than separate buffers per layer: avoids `bind_group` recreation which is expensive and was the root cause of the previous multi-pass rendering artifacts
- All `prepare_layer()` calls complete before any `render_layer()` calls: glyphon's `TextAtlas` can be modified during prepare, which would invalidate bind groups in renderers that haven't rendered yet
- `LoadOp::Clear` on first pass, `LoadOp::Load` on all subsequent: Vulkan marks the texture as undefined until the first render, using `Load` on an undefined texture is UB; `Load` on subsequent passes preserves the accumulated content from earlier layers
- `queue.submit()` called once after all render passes finish: Vulkan command buffers must be submitted as a unit; multiple submits in one frame have caused hangs in prior experiments
