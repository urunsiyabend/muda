## Architecture Summary

The layered rendering pipeline is correctly implemented across all three plans:

**Plan 01 (rectangles.rs):** RectangleRenderer.render() uses unconstrained RenderPass<_> lifetime. render_range(pass, start..end) draws instance subsets without bind_group invalidation. instance_count() getter enables layer range tracking in gpu.rs.

**Plan 02 (text.rs):** TextSystem manages a Vec<TextRenderer> pool sharing one TextAtlas. ensure_layer_renderers() grows pool on demand (never shrinks -- GPU pipeline creation is expensive). All prepare_layer() calls complete before any render_layer() calls, maintaining the atlas stabilization invariant.

**Plan 03 (gpu.rs):** render_frame() groups PaintCommands at LayerBoundary markers. Flat rect buffer with per-layer Range<u32> slicing. First render pass uses LoadOp::Clear; subsequent passes use LoadOp::Load to preserve and accumulate layers correctly. Single queue.submit() per frame (Vulkan requirement). When no LayerBoundary markers present, layer_count=1 -- zero overhead for the common case.

**Wiring:** app_layout.rs composes overlays using stack(), which inserts LayerBoundary markers between children. DialogView uses an inner stack() for its backdrop/body z-layering. All overlay views are properly added as stack() children and generate correct layer boundaries at runtime.
