# Phase 8.1 Plan 02: Multi-Layer TextRenderer Support Summary

**Multi-renderer TextSystem with per-layer prepare/render: one TextRenderer per layer sharing one TextAtlas, preserving all 111 existing tests**

## Performance

- **Duration:** ~2 min

## Accomplishments

- TextSystem now manages a pool of TextRenderer instances (one per layer), all sharing one TextAtlas and Cache — no duplicated GPU textures
- Each layer's text can be prepared and rendered independently: `prepare()` on each TextRenderer clears only its own `glyph_vertices`, so other layers' data is never lost
- `render_layer()` uses `RenderPass<'_>` (unconstrained lifetime) matching glyphon's own render() signature, enabling use in multi-pass render loops without borrow conflicts
- All 111 existing tests pass with zero regressions — changes are purely additive

## Files Created/Modified

- `ora/src/rendering/text.rs` - Added `layer_renderers: Vec<TextRenderer>`, `pending_layers: Vec<Vec<TextEntry>>`, and five new public methods: `ensure_layer_renderers()`, `add_text_to_layer()`, `prepare_layer()`, `render_layer()`, `layer_count()`; updated `clear()` to also clear per-layer pending entries

## Decisions Made

- Used `RenderPass<'_>` (unconstrained elided lifetime) for `render_layer()` to match glyphon's own `TextRenderer::render()` signature and allow calling from loop bodies where the render pass is created and dropped per iteration
- Renderer pool never shrinks: `TextRenderer::new()` registers a pipeline via `Cache`, which is GPU work — reuse across frames is essential for performance
- `pending_layers` cleared in `clear()` (end-of-frame with atlas trim), not in `clear_pending()` (mid-frame without trim) — consistent with the existing pending_buffers behavior
