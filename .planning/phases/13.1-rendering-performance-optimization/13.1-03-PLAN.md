<task type="auto">
  <name>Task 2: FileTreeView viewport virtualization</name>
  <files>ora/src/views/file_tree.rs</files>
  <action>
  Virtualize FileTreeView rendering so only visible rows plus a buffer zone are emitted as elements.

  1. Add fields to FileTreeView for virtualization:
     - `scroll_offset: f32` (pixel offset from top, default 0.0)
     - `viewport_height: f32` (visible area height, default 600.0 as fallback)

  2. Import the row height constant from tree_item.rs (TREE_ITEM_HEIGHT, likely 24.0 or similar). If it's not pub, make it pub.

  3. In the render() method, after flattening the tree into rows:
     ```
     let row_height = TREE_ITEM_HEIGHT;
     let total_rows = rows.len();
     let total_content_height = total_rows as f32 * row_height;

     // Compute visible range
     let first_visible = (self.scroll_offset / row_height).floor() as usize;
     let visible_count = (self.viewport_height / row_height).ceil() as usize + 1;
     let buffer_zone = 20; // half-screen buffer

     let start = first_visible.saturating_sub(buffer_zone);
     let end = (first_visible + visible_count + buffer_zone).min(total_rows);

     let top_spacer_height = start as f32 * row_height;
     let bottom_spacer_height = (total_rows - end) as f32 * row_height;
     ```

  4. Build the container div with:
     - A top spacer div with fixed height = top_spacer_height (if > 0)
     - Only rows[start..end] as tree_item elements (the existing row-building loop, but only for the visible slice)
     - A bottom spacer div with fixed height = bottom_spacer_height (if > 0)

  5. The flat_index used for selection highlighting must still be the GLOBAL index (not the slice-local index). When iterating rows[start..end], the flat_index is `start + i` where i is the iteration index.

  6. Cache the flattened rows: Add `cached_flat_rows: Vec<(usize, FileTreeNode)>` and `flat_rows_dirty: bool` to FileTreeView. Only re-flatten when presentation changes (set flat_rows_dirty = true in set_presentation()). In render(), if not dirty, reuse cached_flat_rows. This avoids re-flattening every frame.
     - Note: flatten_nodes borrows from presentation.roots, which is fine for render() but complicates caching. For caching, clone the node name/extension/is_dir/is_expanded/children info, or store indices. Simplest: clone the (depth, essential_fields) into the cache. Or just always re-flatten since it's cheap compared to layout. Start without caching flatten and add it only if profiling shows it matters.

  7. Add tests:
     - Test that with 100 rows but viewport_height=240 (10 visible rows at 24px each), only ~50 tree_item elements are created (10 visible + 20 buffer each side)
     - Test that top/bottom spacer heights are correct
     - Test that selection index maps correctly for virtualized rows

  IMPORTANT: The spacer divs must have a fixed height set via the style system. Use `.height(px(spacer_height))` or equivalent. They should have no content, just take up vertical space to maintain scroll position accuracy.
  </action>
