# Phase 13.1 Plan 02: Layout Dirty Flag and Cached Layout Reuse Summary

**Per-frame layout caching via needs_layout dirty flag: hover/blink/scroll frames skip compute_flexbox and reuse cached layout_outputs, cutting layout cost to ~0ms on paint-only frames**

## Accomplishments
- Added `needs_layout: bool` dirty flag to `OraApp` — defaults true, reset false after each frame
- Full layout pipeline runs only when `needs_layout || !layout_cache_enabled || cached_layout_outputs.is_empty()`
- Paint-only frames (hover, caret blink, scroll, transition ticks) reuse `cached_layout_outputs.clone()`, skipping the expensive `request_layout + compute_flexbox` calls
- Layout cache hit rate tracked via `layout_hits`/`layout_misses` counters and displayed in `--show-fps` window title alongside glyph hit rate
- `--no-layout-cache` CLI flag added (mirrors `--no-glyph-cache` pattern from Plan 01)
- Conservative invalidation: `has_dirty_entities()` always triggers full layout (covers async file open/save path)

## Decisions Made

**Skip request_layout+compute but keep render():** The element tree is rebuilt each frame via `render()` because Views read model data that may have changed (scroll offset, caret position, hover state). The expensive part is `compute_flexbox` — that's what we skip. Cached `layout_outputs` (element bounds) are valid across paint-only frames because no element sizes or positions changed.

**Scroll events are paint-only:** `MouseWheel` does NOT set `needs_layout = true`. Views read `scroll_top_px` each render() call fresh. The layout (element bounds) doesn't change when scroll position changes; only which content is painted within those bounds changes.

**Mouse clicks mark layout dirty conservatively:** `MouseInput` always sets `needs_layout = true`. Clicks can trigger tab switching (via `dispatch_mouse_down` → tab element handler), command dispatch, or other UI state changes that affect element sizes. Better to have a false layout miss than a false cache hit.

**has_dirty_entities() always triggers full layout:** This covers the async file open/save path where `handle_file_loaded` marks entities dirty and `request_redraw()` is called from the async closure. Since we can't set `needs_layout` from that closure, we catch it in the `window_event` fallthrough check.

**Transitions remain paint-only in about_to_wait:** When `has_active_transitions()` is true but `has_dirty_entities()` is false, `about_to_wait` requests a redraw without setting `needs_layout = true`. Hover color transitions and opacity fades are pure paint operations — element bounds don't change.
