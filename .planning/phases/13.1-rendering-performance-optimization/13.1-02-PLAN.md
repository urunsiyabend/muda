<objective>
Add per-frame layout caching so that when no data has changed (hover, caret blink, scroll), the expensive layout computation (request_layout + compute_flexbox) is skipped and cached layout_outputs are reused.

Purpose: Layout is ~80% of frame cost. Most redraws (hover, blink, scroll) don't change layout. Skipping layout on these frames cuts frame time dramatically.

Output: Layout dirty flag system, cached layout_outputs reuse, paint-only redraw path for hover/blink/scroll, layout hit rate in --show-fps, --no-layout-cache debug flag.
</objective>

<task type="auto">
  <name>Task 1: Layout dirty flag and cached layout reuse in event loop</name>
  <files>ora/src/platform/event_loop.rs, ora/src/element/trait_def.rs</files>
  <action>
  The core optimization: In the RedrawRequested handler, SKIP the full (render -> request_layout -> compute -> prepaint -> paint) pipeline when only paint-level changes occurred (hover, caret blink). Instead, reuse cached element_tree, layout_outputs, hitboxes, and event_handlers, and only re-run the paint phase.

  APPROACH: Track a `layout_dirty: bool` flag on the event loop handler struct (OraEventLoop or equivalent).

  1. Add fields to the event loop handler:
     - `layout_dirty: bool` (starts true)
     - `cached_layout_outputs: Vec<LayoutOutput>` (cached from last full layout)
     - `layout_hits: u64` (times we skipped layout)
     - `layout_misses: u64` (times we ran full layout)
     - `layout_cache_enabled: bool` (for --no-layout-cache)

  2. What marks layout dirty (sets layout_dirty = true):
     - Window resize (WindowEvent::Resized)
     - Any entity change via dirty_entities (self.app_context.has_dirty_entities() at redraw time)
     - Theme change
     - Font size change
     - File open/close/switch (tab changes)

  3. What does NOT mark layout dirty (layout stays clean):
     - Mouse move (hover state change) -- these only need repaint
     - Caret blink timer -- only needs repaint
     - Scroll position change -- only needs repaint (views read scroll offset fresh)
     - Transition animation ticks -- only need repaint

  4. PROBLEM: The current architecture rebuilds the element tree every frame via `self.ora_window.render()`. The element tree is ephemeral -- Views produce new elements each render() call. We CANNOT cache the element tree across frames because Views may read model data that changed.

  REVISED APPROACH: Instead of skipping render entirely, we differentiate between two redraw reasons:

  a) `layout_dirty = true`: Full pipeline (render -> request_layout -> compute -> prepaint -> paint). This is the current path.

  b) `layout_dirty = false`: Still run render -> request_layout (to get element tree with current state) but SKIP compute() and reuse cached layout_outputs. Then prepaint + paint using cached outputs. This saves the expensive compute_flexbox() call.

  Actually even better: The real expense is measure_text() calls inside request_layout AND compute_flexbox. Both are skipped if we cache layout_outputs and skip request_layout + compute.

  BUT: We need the element tree for prepaint (hitboxes) and paint. So we must call render(). The element tree is cheap (Rust allocs are fast per CONTEXT.md). The expensive part is layout.

  FINAL APPROACH:
  - When layout_dirty is FALSE: call render() to get element tree, but skip request_layout + compute. Use cached_layout_outputs for prepaint + paint.
  - When layout_dirty is TRUE: full pipeline, cache the layout_outputs.
  - After painting, set layout_dirty = false.

  5. Determining layout_dirty at redraw time:
     - If `has_dirty_entities()` is true, set layout_dirty = true. HOWEVER, some dirty entities are paint-only (hover, transitions). We need finer granularity.
     - SIMPLER: Add a separate `needs_layout: bool` flag. Set it true on: resize, tab switch, file content change, theme change. Set it false on: hover events, caret blink, scroll, transition ticks.
     - In the event loop, where request_redraw() is called, also set the flag based on the event type:
       * Keyboard input that modifies buffer -> needs_layout = true
       * Mouse click that changes selection -> needs_layout = true (selection ranges change text area layout? Actually no -- selection is painted as overlay rects, layout doesn't change)
       * Mouse move -> needs_layout = false
       * Caret blink timer -> needs_layout = false
       * Scroll -> needs_layout = false
       * Window resize -> needs_layout = true

  6. Implementation: Add `needs_layout: bool` field. Default true. Set it at each request_redraw() call site based on event type. In RedrawRequested:
     ```
     if needs_layout || !layout_cache_enabled || cached_layout_outputs.is_empty() {
         // Full layout path
         request_layout + compute
         cached_layout_outputs = layout_outputs.clone()
         layout_misses += 1
     } else {
         // Reuse cached layout
         layout_outputs = cached_layout_outputs.clone()
         layout_hits += 1
     }
     needs_layout = false  // reset after use
     ```

  7. Add `--no-layout-cache` CLI flag (same pattern as --show-fps, --no-glyph-cache).

  8. Extend --show-fps to include layout cache hit rate:
     ```
     "Muda [{total}ms | view {v} layout {l} prepaint {p} paint {pa} gpu {g} | layout {rate}% | {cmds} cmds | {fps}fps]"
     ```
     (Plan 01 adds glyph rate; this plan adds layout rate. If both are present, show both.)

  IMPORTANT: Be conservative. When in doubt, mark needs_layout = true. A missed cache is just a normal frame. A false cache hit produces visual bugs.

  Specifically, scan ALL request_redraw() call sites in event_loop.rs and classify each:
  - needs_layout = true: keyboard input, resize, tab switch, file operations, theme change, focus change
  - needs_layout = false: mouse move (CursorMoved), caret blink timer, scroll events, transition tick, hover state changes
