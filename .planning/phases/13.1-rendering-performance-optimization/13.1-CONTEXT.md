# Phase 13.1: Rendering Performance Optimization - Context

**Gathered:** 2026-03-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Bring frame times under 4ms for typical editing scenarios (10 tabs, sidebar open) by eliminating per-frame waste in the view tree, layout, and text rendering pipeline. Element/layout caching, viewport virtualization, and glyphon buffer reuse. No new user-facing features.

</domain>

<decisions>
## Implementation Decisions

### Retained Mode Extent
- Selective caching with event-driven invalidation — NOT full retained element tree
- Keep immediate-mode render loop: element tree rebuilds every frame (cheap Rust allocs)
- Cache expensive results: layout computation and text shaping
- Layout checks a dirty flag and skips re-computation if clean
- No view-level render() skipping — always rebuild the tree, just cache layout results

### Glyphon Text Cache
- Global content cache keyed on (line_content_hash, font_size) — shared across all buffers
- Buffer-aware layering on top of the global cache
- Identical lines across buffers reuse shaped glyphs (imports, blank lines, common patterns)
- LRU eviction with a cap to prevent memory growth in long sessions with many files

### Viewport Virtualization
- Sidebar file tree: virtualized with flat list approach — flatten expanded tree into (depth, entry) pairs, single scroll container, uniform row height
- Editor text lines: virtualized — only render visible lines plus buffer
- Half-screen off-screen buffer in each direction (e.g., 20 above + 40 visible + 20 below for editor, ~40 entries rendered for 20 visible in sidebar)
- Editor lines use uniform row height (monospace, no word wrap) — simple math for scroll-to-line
- Tab bar: NOT virtualized (typically <20 tabs, not worth the complexity)

### Cache Invalidation
- Per-view dirty flags — each view (sidebar, editor, tab bar, status bar) tracks its own dirty state independently
- Dirty triggers: window resize, model/data change, theme/font change
- Scroll position change does NOT mark layout dirty — only updates the visible range slice for virtualized views
- Separate paint-only invalidation path: hover transitions trigger re-paint only, never re-layout
- Caret blink uses normal paint-only invalidation via cx.notify(), matching Zed's architecture — no special GPU bypass

### Degradation Behavior
- Skip animations during sustained slow frames (3+ consecutive frames exceeding budget)
- No adaptive virtualization or buffer reduction — trust that caching handles steady state
- When 3+ frames exceed budget: hover transitions become instant (no easing), transition animations skipped
- Recovery: animations resume when frame time returns under budget

### Debug / Observability
- Extend --show-fps to include layout cache hit rate and glyph cache hit rate
- Granular debug flags: --no-layout-cache and --no-glyph-cache for disabling specific caches
- Umbrella --no-cache flag that disables all caching for A/B performance comparison
- Useful for validating optimization impact and isolating cache-related bugs

### Claude's Discretion
- Exact LRU cache capacity for glyphon cache
- Internal data structures for dirty flag tracking
- How to integrate paint-only invalidation with existing transition system
- Specific profiling instrumentation beyond --show-fps

</decisions>

<specifics>
## Specific Ideas

- Match Zed's public GPUI architecture for caret blink: blink manager flips visibility on timer, triggers cx.notify(), layout stays clean, only editor/caret layer repaints
- Sidebar virtualization follows VS Code's flat-list pattern — proven approach for tree views
- Global content cache with buffer-aware layering for glyphon text shaping

</specifics>
