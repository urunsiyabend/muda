# Phase 13.1 Plan 03: Sidebar Viewport Virtualization Summary

**FileTreeView virtualization with spacer-div scroll geometry: only ~60 rows rendered regardless of tree size, sidebar reads SharedScrollState for scroll offset**

## Accomplishments

- Sidebar passes scroll_offset (from SharedScrollState) and viewport_height to FileTreeView each render
- FileTreeView computes visible window via virtual_slice(): start/end indices with 20-row buffer zones
- Top/bottom spacer Divs with fixed pixel heights replace off-screen rows, maintaining scroll geometry
- Selection highlighting uses global flat index (start + slice_i), not slice-local index
- 5 new virtualization tests covering empty list, top of list, mid-scroll, bottom clamp, and selection mapping

## Decisions Made

- **VIRTUAL_BUFFER_ROWS = 20:** Renders at most 10+1 visible + 20 above + 20 below = 51 rows for a 240px viewport with 100 rows. Well under 500+ original cost.
- **Skip row caching:** flatten_nodes is O(n) but very cheap (no allocations per row beyond the Vec). Layout node creation is the expensive part — virtualization eliminates that cost for off-screen rows.
- **Spacer divs not margin/padding:** Div with fixed h(px(spacer_h)) participates in flex layout correctly and is paint-skipped by the GPU renderer when outside viewport.
- **SharedScrollState drives offset:** Sidebar owns the SharedScrollState; scroll_area wraps the FileTreeView output with that state; sidebar reads it each frame and passes to FileTreeView. Clean one-way flow.
