  <name>Task 3: Define run_with_editor() entry point in ora</name>
  <files>ora/src/app.rs, ora/src/lib.rs</files>
  <action>
  This task creates the launch entry point that Plan 08 (thin shell) depends on.

  1. Add `run_with_editor()` function to `ora/src/app.rs`:
     ```rust
     /// Run the application with an EditorDataSource adapter.
     /// This is the entry point for editor applications that provide data through
     /// the EditorDataSource trait rather than building views directly.
     pub fn run_with_editor(adapter: impl EditorDataSource + 'static) -> ! {
         let event_loop = EventLoop::new().unwrap();
         let app = App::new()
             .title("Muda")
             .size(1280, 720);
         let mut ora_app = OraApp::new_with_editor(app, Box::new(adapter));
         event_loop.run_app(&mut ora_app).unwrap();
         std::process::exit(0);
     }
     ```

     This requires adding a `new_with_editor(app: App, adapter: Box<dyn EditorDataSource>)` constructor to `OraApp` in `ora/src/platform/event_loop.rs`. The OraApp should store the adapter in the `Option<Box<dyn EditorDataSource>>` field added in Task 2. If OraApp already has the field from Task 2, just add the constructor.

  2. Re-export from `ora/src/lib.rs`:
     ```rust
     pub use app::run_with_editor;
     ```
     Add this next to the existing `pub fn run(app: App) -> !` convenience function. Also add the EditorDataSource re-export if not already present:
     ```rust
     pub use editor_adapter::EditorDataSource;
     ```

  3. Ensure the function signature matches what Plan 08's main.rs expects:
     - Plan 08 calls `ora::run_with_editor(editor_app)?;` but `run_with_editor` returns `!` (never returns), so the `?` is unreachable. The function should return `!` to match the existing `ora::run()` pattern. Plan 08's main.rs will need to call it without `?`:
       ```rust
       ora::run_with_editor(editor_app);
       // unreachable
       ```
     - Alternatively, if you prefer the `Result` pattern, change the return type to `Result<(), anyhow::Error>` — but then it must actually return. Given the existing `run()` returns `!`, keep `!` for consistency.

  IMPORTANT: The `use` imports at the top of app.rs need to include `EditorDataSource`. Add:
  ```rust
  use crate::editor_adapter::EditorDataSource;
  ```
